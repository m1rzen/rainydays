# R2-02 连续产出与成果入口

状态：verified（仅本批契约）。授权：沿用已批准产品路线与用户“执行下一步”。起点 7de041f，2026-09-28。

## 契约

- 首次生成新 Word/Excel 时展示实际输出目录，可选“本次任务允许新建文档”“仅这一次”“拒绝执行”。任务指一次发送到回答结束，后续消息重新授权。
- 范围许可仅限内置 create_docx/create_xlsx、当前运行、OUTPUT_DIR 根的新建文件；实际写入继续经过路径校验和原子提交。已有文件、其他工具、其他目录、子任务不获得许可。Supervisor 升级确认不能被范围许可跳过。
- 同一任务连续新建只确认一次；覆盖仍逐次确认。拒绝、取消、运行结束和权限退役后不得继续使用。
- 会话中集中展示成功生成的文档，支持预览与继续修改提示；重新打开会话恢复清单。失败及模型口头声称生成的文件不列入。删除或移动后的文件明确无法打开。
- 使用合成资料与确定性模型测试完整运行链。真实模型验收仍需明确批准的测试配置，不调用用户现有密钥。

## Test and design seam

复用 Broker 的精确调用授权；仅增加运行内新建许可，生成一次性、仅输出根、禁止替换的执行上下文。相比全局降低工具审批级别，这保留原有边界且无配置迁移。PathPolicy 的预检公开目标是否存在和规范路径，提交仍绑定私有身份。

成果取自已持久化的成功工具消息及文档工具的结构化回执，不增加数据库表或另建成果存储。历史消息不会因内存摘要被删除；重试回滚会按现有消息语义移除相应记录。原文件可能被用户移动，打开时复用 File Viewer 检查。

公共验证接口：真实 Agent + Broker + PathPolicy + 文档写入；用户交互通道；会话消息恢复；真实 Electron 的成果列表与预览入口。研究依据见 technology-stack.md 的 R2-02 节。

## 实现与评审

复用原审批/原子创建与消息历史，未引入新权限框架、依赖或数据库版本。成果入口沿用现有界面；继续修改会保留用户草稿并追加文件与另存要求。

[Standards/Spec 评审](../work/r2/reviews/02-code-review.md)，[桌面诊断](../work/r2/diagnostics/02-output-flow.md)。首个产品行为测试先红（3 次确认），实现后绿（2 次：一次范围许可、一次覆盖询问）。
