# R2-01 文档附件与分段读取

状态：verified（仅本批契约）。授权：用户要求进入下一阶段，沿用已批准路线。起点 ed6afd2。

## 本批契约

- 上传 PDF/DOCX/XLSX 并保留原始字节、哈希、会话归属；兼容原 text/image 存储。实际测试发现数据库 MIME 白名单也需扩展，增加 11→12 事务迁移并验证旧附件保持不变。
- 文档以及较大文本只向模型提供附件索引，由现有 read/read_file 按 `attachment:ID` 分段读取。读取范围由当前会话决定，附件句柄不转发远程 Worker。
- 返回文件名、提取行号、下一段位置；长单行也能完整翻页，不静默截断。
- 复用已有隔离解析、文档生成、File Viewer 预览。损坏文档和无文本扫描 PDF 明确失败，不冒充已读。
- 验证上传到绑定、模型索引、读取首段与后段、会话恢复及跨会话拒绝，并验证 Word 输出可再读并修改。

本批不改变写入授权；任务范围内新建输出许可仍为 R2 后续任务。Office 预览为已有提取文本预览，不承诺原版式编辑。实际模型质量另测。

## 设计与研究

已有 `parseDocumentIsolated` 支持 PDF/DOCX/XLSX；复用现有 worker、资源归属和取消机制。`read_file` 已代理到 read。使用附件句柄扩展已有读取接口，避免新增工具、权限体系和存储层。

`attachment.kind=text` 表示文本型资料，MIME 区分二进制文档与 UTF-8。验证签名后入库，解析在隔离 worker 中按需执行。`projectMessagesForProvider` 不把二进制解码成 UTF-8。

测试公共接口：附件存储、Provider 消息投影、readExec、createDocxExec，以及真实 Electron 上传入口。使用合成资料与现有两页 PDF 测试文件。
