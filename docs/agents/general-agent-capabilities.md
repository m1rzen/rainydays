## 2. 同一运行链中的最小接口

沿用现有 invocation、execution、session 与 tool result 类型。先验证它们是否已表达以下信息，缺少再增字段；以下是行为要求，不要求创建同名框架。

1. 能力状态：可用/缺依赖/未配置/当前模型不支持/等待用户；包含可操作原因。
2. 调用关联：run、tool call、工作范围、取消信号、资源所有者；结果包含实际状态与错误种类。
3. 输出：文本、结构化数据、可继续获取的长输出、图像、成果文件引用。上下文预算包含schemas、图片和返回值。
4. 副作用结果：实际修改的文件/远端对象、退出状态或未知；未知不等于失败可安全重试。
5. GUI观察：目标窗口/标签页、时间与版本、尺寸/DPI、UI引用或图像。动作引用该观察；过期时先重取。
6. 用户可见：当前阶段、等待原因、结果/差异、停止/接管；复用对话和按需面板，不恢复堆满内部名词的工作台。

不建立另一套Agent内核、通用RPC平台或企业审批总线。具体代码边界由当前票据的真实调用路径决定。

## 3. 代码与 CLI：完成开发循环

A03/A15增量（2026-10-25）：按批准的规格§7，开发模式使用用户工具链，默认助手真实命令/中文cwd、61秒终端、1600行分页/stdin/exit7、取消与owner拒绝、缺依赖提示及真实renderer任务确认/只读面板已验证；可与活动手动隔离终端共存，任务结束保留手动进程。同事模式的SDK接入、Node子进程pipe、多个native host租约与三项认证拒绝观察失败仍保留为后续项；没有通过隔离失败静默切换模式。真实模型与安装/MCP交付仍待各票。限制与证据见[A03](../work/general-agent/tickets/03-cli-sessions.md)。

- 开始先识别仓库根、Git状态、项目脚本/测试和作用域内AGENTS.md。`read_repo`当前依赖`git ls-files`，不能据此忽略用户未跟踪文件；用受控遍历补齐必要上下文。
- 修改基于读取内容的前提。保存基线摘要或原片段；文件已被用户/其他工具修改时重读并合并，不盲写。只撤回本次可证明的变化，不用`reset --hard`清理用户工作。
- CLI首先使用已有执行与持久终端。实际运行项目命令，读取退出码和关键输出；流被截断时能分页取回。长任务不受短命令工具固定30秒设计绑死。
- 开发模式以用户工具链运行普通构建/测试；同事模式的隔离限制明确说明。隔离若阻挡合法依赖，不能默认提权、全盘授权或静默回退；用户必须在本机显式选择开发模式。自建隔离SDK等兼容实验按规格§7后移。
- 依赖缺失给出命令与安装选项，安装外部依赖需要符合当前任务授权。不要在没有Node的同事电脑上把npm失败报告成代码有错。
- 执行失败→定位→修改→重跑受影响检查；默认最多3次自动修正，超限汇总证据/建议，允许用户继续。无变化的同一失败不循环重试。不要把模型写出的测试通过文字当事实。
- 最终给出改动摘要、差异入口、检查命令/退出结果和未验证项。代码默认在用户所选仓库编辑，Office成果默认另存；两种行为不混淆。

## 4. MCP：真正的协议接入

A05增量（2026-10-30）：[本地stdio票據](../work/general-agent/tickets/05-mcp-local.md)已verified，SDK1.32.1；設定測試後新會話按需發現schema，首次獲Broker任務授權才啟動。Windows Job使用者管道後端沿用root資格與owner，取消/崩潰/app退出均有真實程序清理fixture。這不代表同事隔離stdio、遠端認證或安裝/真實模型已驗收。

采用官方 TypeScript SDK，实施时锁定兼容版本并测试。先stdio，再Streamable HTTP；不另写JSON-RPC协议栈。配置界面、客户端生命周期和真实工具目录一起交付，更新version/capability元数据与相应测试。

- 用服务器ID命名空间隔离同名工具；分页列举与列表变化后刷新；运行中的调用绑定发现时的schema版本。只加载与任务相关的工具，不能假设名称永远不变。
- JSON schema参数校验、工具错误、进度/取消、text/structured/image/resource内容映射到现有工具结果。资源按需读取，内容作为资料，不变成权限或系统指令。提示模板可列出为选用资料，不能替换系统约束。
- stdio子进程明确command/args/cwd与许可环境变量，stdout只读协议、stderr作为有限日志；请求超时、退出、取消与应用退出清理。第三方进程并不天然受到RainyDays文件工具范围限制，必须通过已有受控执行接口满足声明权限。
- HTTP支持会话、JSON/SSE响应、协议协商、token和常见OAuth登录；复用SDK与系统浏览器，不自造身份平台。凭据引用现有vault，日志不含token；用户可断开/移除。
- 断线后只对确定无副作用的发现/读取作有限重试；调用超时或写入响应丢失标记未知，不能重连后再执行一次。远端服务器已执行的工作不能靠本地取消撤销。
- 外部MCP服务权限与本地文件沙箱分别说明；服务声明的readOnly等注解是提示，宿主不能把它当权限证明。自定义服务器须可用，不限于内置白名单；认证和服务环境仍需用户配置。

## 5. 浏览器与原生 Windows 分开实现

浏览器先CDP，优先DOM/可访问性引用，必要时截图视觉。当前部分click/type/press靠脚本事件，真实Enter/Tab、表单提交、剪贴板、文件选择与跨源框架不能由这些实现自动保证；用真实输入和固定网页验证。下载必须关联实际完成文件，上传限定用户选择范围。不要遍历用户其他会话。

Windows采用薄的UI Automation + Win32输入/截图helper，接口置于现有工具适配层。A01验证实现与分发选型，例如可随包运行的.NET自包含helper；不预先要求用户安装PowerShell模块/开发SDK。先列窗口和读取UIA，再补截图与目标窗口动作。

该helper须在用户交互会话中以标准用户身份运行，无法直接套用隔离子命令的AppContainer来控制其他应用。仅由已授权run经现有宿主认证接口调用有限的窗口/观察/动作接口；不暴露任意shell或反射执行，不提升管理员权限。具体会话和生命周期边界由A01/A09验证，不能为了GUI顺便解除普通CLI的隔离。

每次动作前核对目标PID/窗口句柄、当前前台和观察版本；窗口移动、缩放、失焦或弹出新窗口后重新观察。坐标要区分截图像素、物理屏幕位置与DPI缩放。Unicode/中文输入、修饰键释放、拖动和剪贴板临时使用均须有限行为测试。

Windows全局输入存在焦点竞争，UIA也并非所有控件可用。使用目标控件操作优先，注入全局输入前再次核对并缩短动作批次；焦点变化立即暂停。不要宣称目标窗口检查能从系统层面绝对隔离输入。UAC/高完整性窗口不能通过普通SendInput保证操作，按人工接管处理。

## 6. 图像与 Computer Use 循环

工具截图经过图片结果适配送入支持图像的模型，保留call关联、尺寸、目标与时间。记录传输是否实际发生，限制分辨率/数量和保留时间；仅保存文件路径不能算已观察。若压缩缩放，动作坐标必须反算回正确屏幕位置。

初始默认上限：每任务50个GUI动作、总10分钟；连续3次没有状态进展暂停求助。复杂任务可事前调整。每个会改变目标的动作后观察；只有明确稳定的短输入序列可批量。视觉模型说“成功”还须文件、DOM/UIA或截图的结果检查支持。

用户能看到控制目标并随时暂停/接管/停止。暂停/取消本地反馈≤1秒，立即阻止排队的新输入；在途单个系统动作可能已发生，需显示最后结果。恢复时重新观察，不重放旧坐标。不要在后台隐蔽控制用户正在使用的另一个应用。

## 7. 技能、子任务与验证

技能是按需加载的任务知识，不是新的权限系统。项目指令按目录范围与优先级解释，外部仓库内容不能授予访问密钥或其他项目的权限。技能可见可关闭，参考材料按需读取，保留现有.md兼容性。

有界子任务复用现有实现：默认并发≤2、无递归、只读研究/审查为先；父任务负责最终结论和写入。同一仓库不让多Agent同时改相同文件。要启用独立写入时另设明确工作树与合并契约，本版不以此为门槛。停止父任务后禁止子任务继续派生或写入，保存已完成结果。

复用已有 terminal-owner、rt10-terminal-interruption、sec01-terminal-owner、tool04-script-runtime、tool04-script-native、rt04-child-cancellation、eco08-browser-session/cdp 等测试作为相关起点；文件名实施前以仓库实际内容核对。不要为每个工具复制一套测试平台。

最终验证入口是普通默认助手和当前安装包。测试驱动绕过允许列表、直接调用工具函数或伪造视觉回答，只能证明局部工程，不能计为产品交付。
