# RainyDays：Codex 专用研发手册

日期：2026-10-18。源码依据417039e，上一版规划提交5ee1580。用户确认参照本机Lux Desktop v0.1.898，并进一步要求代码、CLI、MCP和强Computer Use。本次扩展规划保持proposed；已有R1–R5授权与证据继续有效，计划不等于实现完成。

**最终目标：同事安装后，用一个默认助手完成文件与研究、可编辑文档、代码修改与测试、CLI、MCP、浏览器和Windows应用操作，并能停止、接管、恢复和检查成果。** 技能与有限子任务帮助完成这些工作。Prism、钉钉排除。

## 一、阅读与执行顺序

1. [STATUS](../STATUS.md)：当前事实、阻塞与下一步。
2. [通用Agent规格](../specs/general-agent.md)：最新完整范围；基础文件/研究/文档行为见[基础规格](../specs/colleague-delivery.md)。
3. [D+A总任务图](../work/general-agent/plan.md)：18项基础任务+13项新增任务，按真实依赖选择第一项已批准工作。
4. 只读当前票据的研究与代码，按[workflow](workflow.md)实施；有界研究见[Lux计划](../research/lux-reference-plan.md)。
5. 进入发布时读[通用验收](general-agent-acceptance.md)和[发布维护](release.md)；给同事的材料为[指南](../user-guide.md)。

修改运行链看[架构](architecture.md)；开发代码/CLI/MCP/浏览器/桌面/技能/子任务看[能力手册](general-agent-capabilities.md)和[技术依据](../research/general-agent-stack.md)；权限或执行边界变化看[安全预算](safety-budget.md)。不必每次加载全部文档或历史parity报告。

## 二、何时算交付

| 阶段 | 必须达到 | 能说明什么 |
|---|---|---|
| 工程可运行（当前） | 部分源码测试与真实桌面流程有证据；模型和安装缺口仍在 | 供开发继续验证 |
| 基础工作流里程碑 D15–D18 | 原四类40次任务与基础安装/试用标准 | 可交付限定基础能力，不能称完整通用1.0 |
| 通用Beta | 100次任务≥85、每组≥8/10，无P0/P1，支持矩阵与安装通过 | 向知情同事提供完整能力试用 |
| 稳定通用版 A13 | 同候选≥95/100、每组≥9/10；三人五工作日≥30项、≥90%无需作者救场；发布/维护齐备 | 支持范围内的成熟同事版 |

具体样本、计分、环境与试用覆盖只由[通用验收](general-agent-acceptance.md)管理。不能用40次办公任务通过代替代码、MCP或GUI质量；也不能宣传任意任务成功率。

## 三、当前差距

现有内核值得复用。文件、文档、来源、UI、部分恢复已有工程证据；此前26项产品回归和15项UI/IPC通过，本次文档更新未重跑。五项真实研究因模型额度失败，旧数据工作台还有未定位问题。

CLI/持久终端已有实现但默认助手接入不足；MCP仍是配置与关闭状态；浏览器缺完整产品验证；原生Windows操作尚未成为产品能力；截图到模型的完整观察链未验收。因此旧方案不足以保证新增目标，已用A系列补齐。

## 四、给下一次Codex的任务指令

> 阅读AGENTS.md、docs/STATUS.md和docs/work/general-agent/plan.md。从已批准且依赖满足的任务开始，先核对代码与实际证据，再完成用户路径及必要验证，更新票据和STATUS。默认助手必须能使用新增能力。D18是基础里程碑，A13是完整交付；不要把MCP、单浏览器、Windows操作和有界子任务重新后移。复用现有内核与保护，Prism、钉钉不做。外部模型或环境阻塞时推进独立工程，未执行的验收不能标绿。

整套路线获批后可连续执行，不逐票重复确认。新付费测试、账号配置和实际对外发送核对具体授权；既有授权按原范围延续。

## 五、投入控制

- 一次一个主要用户切片和必要阻塞修复；每阶段有普通会话可演示结果。
- 55–90工作日工程，另计5工作日试用，约12–20周；假设一位熟悉项目的维护者持续配合Codex，外部等待另计。A01技术探针2–3日后重估。旧6–10周只对应较窄范围，不能沿用为完整交付期限。
- Lux研究总计约5–8人日，包含基础研究，已计入工程估算；只回答当前能力问题，不完整反混淆。
- 新安全/治理框架投入约10%、上限15%；真实严重缺陷必须修复。不要把GUI目标核对或MCP认证扩成新的企业平台。
- 两周没有新增用户结果，停止扩张并做最小瓶颈实验。商业产品级成熟度须由模型、驱动、安装与用户实测共同证明，任何文档都不能保证必然成功。
