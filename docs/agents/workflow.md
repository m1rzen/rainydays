# Codex 执行流程

适用于同事版 D 系列。产品定义见 [规格](../specs/colleague-delivery.md)，优先级见 [任务图](../work/colleague-delivery/plan.md)。流程服务于可交付结果，不增加逐卡角色仪式。

## 开始与恢复

1. 读取 STATUS、当前票据，核对 Git 状态、当前代码和依赖票据证据。保存其他人的改动；不得为了得到干净树清空 WIP。
2. 用一句话说明本票的用户结果、已知问题、验证入口。先读调用者及相邻状态，再修改。
3. proposed 需整套计划或该项获批准后才转 ready；原已批准任务沿用授权。ready → in-progress → implemented → reviewed → verified。blocked 必须写明外部事实和解除条件。
4. 只做当前票据及有直接依赖的修复。新需求写入候选；不是顺手重构的理由。

## 实施与验证

- 已知缺陷先获得可失败的复现；新增行为通过现有公共接口验证。文案/低风险样式无需写镜像实现的测试。
- 每票至少演示一次用户可观察结果；覆盖该票明确的错误、取消或持久化场景，不为不涉及持久化的文案增加数据库测试。
- 日常使用 `npm run check:product`；首次或解析 worker 改动后先 build。桌面改动选择相关真实 Electron；该命令现有筛选不包含全部新入口/R4/R5，要按票据选择补充用例。
- 权限、路径、凭据、原生执行变动，运行对应既有负向/取消检查。发布才跑当前候选与安装路径。具体命令从 package.json 和测试文件查，不复制几十个旧治理命令。
- 不把所有旧 governance 清单刷新设为日常前置；若它阻塞当前构建，先分辨真实行为失败和历史元数据过期。只修必要范围并记录理由，不能改期望掩盖缺陷。
- 同一失败两次没有新证据时停止盲跑，提出能区分假设的最小实验。两个连续工作日没有可演示进展，拆小当前票或明确外部阻塞。

## 审查与结束

分别核对仓库规则和票据验收。一般票可按固定 diff 顺序审查；数据迁移、执行权限与发布更改需要独立复核。可以在用户/技能已授权时委派，否则顺序检查并如实注明；不要搭建新的审查服务。

完成记录只需：改动目的、起点/终点提交、测试命令与结果、对应验收、未测项、风险/回退。附在票据；复杂缺陷才另建 diagnostics，跨票重要决策才另建 ADR。普通票无需同时写多份重复证明。

更新 STATUS 的下一步与阻塞。每个完整切片本地提交，精确暂存文件；不提交用户数据、不自动推送。若未全部满足验收，保持 implemented/reviewed 或 blocked，不能勾选 verified。

## 阻塞处理

- 模型额度/密钥：不试其他已存密钥；保存失败事实，推进不依赖真实调用的工程任务。
- 安装机器/同事不可用：完成候选和说明，保留发布 gate 未通过；不伪造干净机器或人工试用。
- Lux 无法启动或版本不符：按参考计划记录 unknown，使用 RainyDays 的产品验收继续；目标行为不是必须复制的私有实现。
- 用户数据场景：优先合成/脱敏副本，保留原数据；修复工具需要预览和恢复前快照，不允许旧库覆盖新库。

## 文档各自负责什么

STATUS 记录现在；规格定义行为；任务文件记录依赖与验收；acceptance 定义计分；research 记录外部事实；devlog 保留过去。修改事实时更新所属文档，其他位置链接引用。
