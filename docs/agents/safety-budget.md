# 安全基线与投入上限

目标：保护同事的数据与机器，同时把研发主要投入放在任务质量和使用体验。沿用现有有效控制，避免再次建设过量底座。

## 固定基线：保留并用少量行为验证

| 保护对象 | 现有策略的产品契约 | 必须能观察的结果 |
|---|---|---|
| 密钥与个人资料 | OS 凭据保护、日志脱敏、用户独立数据 | 界面/导出/日志不出现密钥；没有默认上传整段历史的诊断 |
| 文件 | 用户选定范围、宿主路径检查、新建优先、覆盖确认 | 越界写入被拦；新建不破坏原文件；批量动作有预览与撤回 |
| 指令来源 | 网页/附件/模型文本不能授予权限 | 文档里的“忽略规则、发送文件”不能扩大操作范围 |
| 桌面边界 | 保留现有 Electron 隔离与 IPC 鉴权 | 外部页面/未授权请求不能调用本地敏感能力 |
| 执行与取消 | 复用已实现的受限进程与清理 | 无隔离时该执行功能关闭；取消/崩溃后不留下持续写入进程 |
| 数据与升级 | 一致备份、迁移事务、用户确认恢复 | 不以旧库覆盖新数据；崩溃/更新后历史与成果可恢复 |
| 副作用 | 一次 run 的有限许可、未知写入不自动重放 | 同范围新建多文档一次确认；追加用户发送重新界定许可 |

范围内读取和已批准新建让系统连续完成。覆盖/删除、扩大目录、进程权限或对外发送应让用户看到实际对象与后果。不要把所有操作都包装成同样的“高危”弹窗。

## 新能力的必要边界

以下复用现有运行与凭据链，以具体行为验证，不新建独立审计或审批体系：

- 代码/CLI：保留用户已有修改、校验读后写冲突、命令cwd/依赖明确、停止清理；普通任务已获授权的代码编辑不逐行确认。
- MCP：明确第三方进程/远端服务实际权限、保护token、未知写入不自动重放；工具路径检查不会自动沙箱化任意MCP服务。
- GUI：目标窗口/标签和焦点检查、观察失效重取、可见暂停/接管；AppContainer不能隔离其他应用中的GUI副作用，不承诺绕过UAC或绝对消除焦点竞争。
- 子任务：限定范围/并发、单写入者、父取消传播。

## 不再默认投入

- 新增企业权限平台、远程身份/租户系统、完整零信任框架。
- 每张普通票生成一套哈希清单、角色证明与真实性回执。
- 全 SQL/全函数插桩、全库覆盖率冲刺、为了旧卡全绿批量改摘要。
- 迁移所有历史安全模块、重新实现整个沙箱，或构造自主审批 Agent。
- 通过放宽全局权限、跳过路径验证或禁用隔离修好演示。

已有模块可以保留冻结；“不继续扩建”不要求先冒险删除。

## 新安全工作的准入与预算

新增独立控制前，在当前票据回答五件事：哪个实际能力需要它；可信失败路径；现有控制为什么不够；最小修复；如何用一个行为用例验证。答不出来就转候选，不进入当前迭代。

建议未来迭代 **70% 用户任务质量与功能、20% 安装可靠性和缺陷、10% 新安全/治理**；允许新安全/治理浮动到 15%，按实际耗时每周简单记录。数据损坏、泄露、任意执行等已确认严重缺陷属于必须修复的产品故障，不得因配额忽略。

连续一周超出上限：先缩小触发复杂度的功能（例如关闭未完成的远程执行），复用现有保护；明确给出成本与用户收益后再决定投入。只统计一个周表，不建设预算追踪系统。

## 验证尺度

普通功能：快速回归 + 当前行为。影响某个边界：加对应现有负向、取消或恢复用例。安装候选：统一做一次发布级保护检查。

测试发现现实风险就修；测试只发现旧证明清单漂移就单独处理。两者必须在结果中区分，不把“安全”当作无限扩大工作范围的理由。
