# 基础工作流验收与任务集

本文件负责D系列四类20项任务和基础质量规则；2026-10-18扩展后的完整通用版由[通用验收](general-agent-acceptance.md)统一定义。这里的Beta/稳定门槛仅表示基础工作流里程碑，不能代替A13完整交付。

本文件拥有结果计分规则。所有数字为 **待实测的目标**，不是当前成绩。真实评估需要明确批准的模型配置、任务数量、费用/时间上限；提供方故障记为未完成，不能过滤成成功。

## 1. 四层证据

| 层 | 验证什么 | 不能代替 |
|---|---|---|
| 确定性行为 | 本地模型桩、真实解析/文件/DB、取消与错误分支 | 模型推理质量 |
| 源码 Electron | 实际 renderer/IPC/后台、旧数据脱敏副本、重启 | 干净机器的安装 |
| 当前安装候选 | 必要依赖、迁移、恢复、停止、成果打开 | 同事独立完成任务 |
| 真实模型与试用 | 事实、文档、选择工具、耗时与学习成本 | 支持范围外的普遍保证 |

已有用例先复用，新增用例只补缺口。记录 commit、build、模型/配置、系统与任务输入版本；真实模型不缓存成功答案当作新运行。

## 2. 固定 20 项，四类各五项

D15 开始时将以下规格落实成脱敏 fixture、用户提示与 **运行前写好的预期结果**。fixture 与 rubric 可进入 tests/fixtures；模型输出/截图/含内容的日志保存在忽略目录。每项跑两次独立会话，共 40 次，预先决定顺序；选最优一次不算通过。

| ID | 输入与用户任务 | 必须检查的结果 |
|---|---|---|
| F01 | 文本 PDF 约 30 页，关键期限置于第 17 页，请提取期限与责任人 | 与预期文字一致，页码可核对；读取不静默截断 |
| F02 | 两份 DOCX 对同一活动的日期/人数互相冲突，请整理差异 | 两种说法及文档/段落依据都出现；不自行挑一个当确定事实 |
| F03 | XLSX 两张表，含数字/日期/文本与公式缓存，请汇总地区销售 | 人工预先算定总额，类型正确；缓存缺失时说明或经可靠计算，不猜 |
| F04 | TXT/MD 长单行与长表格混合，指定中段编号并追问原句 | 首答和追问均取回正确片段；压缩/重启后仍可定位 |
| F05 | 有效文本 PDF + 扫描件或损坏文档，请列资料摘要 | 有效文件完成；不支持/解析失败单列，无虚构摘要 |
| R01 | 既有 RESEARCH-01：Electron 三项安全概念 | 沿用既有人工条件，至少两个实际读取官方来源，Word 可编辑 |
| R02 | 既有 RESEARCH-02：AbortController 与服务端副作用 | 事实/推断分开，来源实际读取，概念不混淆 |
| R03 | 既有 RESEARCH-03：Word Open XML 与生成库 | Word 与核对表可打开，引用对应已读资料，一次新建范围审批 |
| R04 | 既有 RESEARCH-04：不同年份虚构销量比较 | 24 与 21 的时间范围不同，不能直接宣称同年增长 |
| R05 | 既有 RESEARCH-05：一个无法访问来源与替代来源 | 失败可见，至少两个有效来源，不引用未读网页为证据 |
| O01 | 虚构季度数值与结论要求，生成 Word 简报 | 标题、摘要、事实表、结论正确；目标软件视觉检查无裁切 |
| O02 | 虚构销售明细，生成 Excel 汇总与明细页 | 预定总额与类型正确；表头可读；若用公式检查计算值及缓存策略 |
| O03 | 同一请求生成 Word 与 Excel | 两个实际文件，字段一致，成果区可打开；范围内一次审批 |
| O04 | 修改 O01，新增一条反馈并缩短摘要 | 默认另存，原版字节不变；新版内容正确，重启后两者可区分 |
| O05 | 整理 12 个测试文件，其中 2 个目标重名 | 预览后只执行无冲突项；冲突可见；撤回恢复可验证的原状态 |
| T01 | 将已通过的季度报告任务存成模板，换一组数字运行 | 新结果使用新数字；新 run，不带旧凭据或许可 |
| T02 | 模板换输入文件夹与输出文件夹 | 范围在执行前清楚；成果只出现在本次选择位置 |
| T03 | 模板缺必填输入、随后补齐 | 缺项阶段不发模型请求；补齐后完成；历史运行保留 |
| T04 | 模板生成中取消，重启后选择再运行 | 已成功文件保留，未完成状态清楚，无自动重复写入 |
| T05 | 从模板生成报告，再用普通对话修改并另存 | 两条路径复用同一运行与成果逻辑，修改可核对 |

研究的详细预期继续由 [R4 真实评估](../research/R4-model-evaluation.md) 管理。复用既有五项可节省重复设计；只有候选、输入和计分完全相同的实际运行才可计入本轮，旧失败/旧版本测试不能算当前成功。

## 3. 成功、失败与人工介入

每次成功必须全部成立：用户要求满足、关键事实/数字正确、成果可打开编辑、资料依据可核对、没有开发者修改源码/数据库/配置救场。必要的用户澄清、指定路径和风险审批属于正常交互，但记录次数。为了纠正错误答案而追加指令算 correction，另列；不能把被纠正的首次失败抹掉。

基础Beta：≥34/40，每类≥8/10。基础稳定里程碑：同一冻结候选≥38/40，每类≥9/10。未完成、超预算、中断、输出错误都记失败，并分类 provider / retrieval / model / tool / UI / package。完整通用版采用100次及每组门槛；小样本只支持该任务集与环境，不能宣传“95% 任意任务成功”。

有严重问题先修复再验证；每次修复重跑受影响任务。基础稳定门槛用冻结候选完整一轮40次，完整通用版用100次；避免每个小改动都重跑全套收费任务。旧候选保留结果，不混合分数。

## 4. 性能与可靠性目标

参考环境：D13 记录的 Windows 11 x64、16 GB 内存、SSD 标准用户机；模型时延与本地响应分开测。

- 冷启动到可操作目标 ≤10 秒，连续 10 次；超时须定位，不为凑平均值丢样本。
- 发送后本地任务状态 ≤1 秒；取消反馈 ≤1 秒，受控工具及进程清理目标 ≤5 秒。网络已发生的远端处理不声称能撤销。
- 测试中无无限 spinner；慢调用显示当前阶段和可取消入口。任务集默认每次 5 分钟预算，任务较大需事前规定而非失败后改门槛。
- 20 轮混合长对话完成后，界面可继续操作，能找回早期事实；连续 2 小时混合读写/停止/切换后无崩溃及孤儿进程。
- 重启 10 次、网络中断、模型额度失败、目录断开分别有明确结果。数据恢复验证内容/附件，而不只统计行数。
- 记录模型请求数、tokens、估算/实际费用、首响应和完成耗时；没有 usage 或价格就写未知，不能按字符串长度伪造账单。

## 5. 停止分发的缺陷

P0：数据丢失/不可恢复覆盖、密钥泄露、越权副作用、重启重复危险操作。P1：支持环境无法安装/启动、主要任务持续失败、不能停止、历史或成果不可达。发现即停止该候选分发并修复。

P2：有明确绕行方式的次要体验问题；记录影响、临时做法与计划，可小范围试用。外部提供方停机不是应用缺陷，但该批真实任务仍未通过；不能把提供方不可用描述成产品完成。

## 6. 三位同事的试用

三位非开发者在至少两台干净机器/标准用户环境中自行安装；清楚说明测试数据可发给哪个提供方。每人使用 5 个工作日、至少 8 次支持范围内任务，总量至少 30 次，覆盖四类且每类≥5次。

目标：≥90% 无作者救场完成；三人都在说明指引下 10 分钟内完成配置与首个任务。记录失败时刻、版本、类别、所需帮助与用户自己的满意原因；不给成功台词代写试用报告。

D16 完成表示试用证据收齐；不自动表示产品通过。D17 修复后必要复试，D18 检查稳定候选、真实试用与全部 P0/P1 同时闭合。

修复前后的试用分开统计。稳定版须有满足上述人数、次数与 90% 目标的五工作日窗口；若初次窗口已达标且无严重缺陷，保留它并复测后续受影响路径即可。若未达标或发生严重回归，修复后重新取得合格窗口，不能把早先失败改写为成功。

```text
开始、首反馈、结束 / 请求数 / usage / 费用或未知：
状态：pass | fail | blocked
输出与来源位置 / 人工核对人及结论：
审批次数 / 澄清次数 / 错误纠正次数 / 是否开发者救场：

```

行为证据、实际模型质量、用户接受度分别记录。不要再建一套逐票真实性签名系统。
