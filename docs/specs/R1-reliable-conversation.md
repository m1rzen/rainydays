# R1：资料完整性与回答断流恢复

状态：依据用户 2026-09-28 对产品路线的实施授权，当前实施。

## 用户可见契约

1. 工具返回的资料在预算以内完整进入对话；单行 JSON、中文长文本不能被固定 1500 字符截断。数据库恢复后保持相同内容。
2. 超预算只摘要旧消息；最近消息保持完整。无法满足预算时明确报错并提示在新会话缩小读取范围，不以静默丢资料继续回答。原始记录仍在数据库。自动分页及同会话超预算恢复留给后续文档切片。
3. 摘要边界不能把一组工具结果漏掉。取消或无法满足预算时，不提交半完成的内存变更。
4. 流建立前的暂时性错误可重试；流建立后的错误不重新请求，不拼接两次回答，不执行半截工具参数。只有兼容接口返回 stop/tool_calls 完成原因时才成功；提前关闭、达到长度限制或过滤中止要明确失败。
5. 已显示的本轮文字在模型断流时保留，并显示未完成提示；历史恢复后内容一致。普通完成和取消保持原有语义。

## 实施选择

复用 ConversationMemory、LLMClient、Agent 和现有界面。删除无条件工具内容压缩，在 compact 入口和提交前验证预算；保持现有旧消息摘要和回退机制。LLMClient 在建立流后关闭重试。Agent 保存已发送的本轮文字加错误提示，界面保留已收到文字。

公共测试接口：ConversationMemory.addMany/loadFromDb/compact；真实本地 HTTP SSE 服务与 LLMClient.chatStream；Agent.run 与临时 SQLite 会话。不用私有 SDK 字段替换来证明流行为。

## 验收与边界

测试覆盖单行长内容、重启恢复、预算溢出、工具组摘要、网络重试、文本断流、工具参数断流及正常完成。使用假凭据和回环地址。定向测试、类型检查、相关静态检查、独立评审后记录结果。

本切片不新增权限系统、不降低现有隔离，不承诺 PDF/DOCX/XLSX 输入已可用，不把源码测试等同于安装包验收。
