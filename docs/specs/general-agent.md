# RainyDays 通用 Agent 交付规格

Status: approved

批准：2026-10-18，用户明确批准当前D+A路线并要求连续实施。本文件为最新范围依据；获批不代表代码完成。原[基础工作流规格](colleague-delivery.md)继续适用于文件、研究、文档和手动重复任务。两者冲突时，以本文件扩展范围和最终交付标准为准。

## 1. 目标与判断

目标是供少量熟悉同事使用的 Windows 通用桌面 Agent：用户提出目标，它能获取上下文、选用工具、连续执行、检查结果、修正错误，最后交付可检查的文件、代码修改或应用状态。默认界面保持已经通过的安静对话与成果设计，终端、步骤、截图和工具配置按需展开。

上一版 D01–D18 足以指导基础工作流成熟化，**不足以交付本规格**：MCP 尚未实际接通，默认助手未开放完整开发工具，浏览器缺完整产品验证，原生 Windows 操作尚未形成能力。扩展任务不能继续留作可选候选。

技术路径可行，但当前没有证据保证达到某一商业产品的整体成熟度。可承诺按功能契约实施、以真实任务检验；不能保证任意模型、程序或网站都可可靠操作。完整逆向 Lux 不能替代模型质量、工具适配和实测。

## 2. 必须交付的能力

| ID | 用户目标 | 完整行为与交付物 | 主要任务 |
|---|---|---|---|
| G01 | 处理资料与产出文件 | 检索长文件、核对来源、生成并修改可编辑文档、保存任务再运行 | D03、D06–D11 |
| G02 | 理解并修改一个代码项目 | 识别工作目录和项目约定，读取相关文件，保留已有改动，实施多文件修改，展示差异 | A02 |
| G03 | 调用本机 CLI 完成工作 | 确定 cwd、运行环境与依赖，执行命令，读取退出码和增量输出，必要时输入，取消并清理进程 | A03 |
| G04 | 修复代码直到有验证结果 | 发现失败→修改→运行项目检查→读取真实结果→有限修正；最终解释改动、已验证项和剩余问题 | A04 |
| G05 | 接入 MCP 工具 | 用户添加 stdio/Streamable HTTP 服务，发现并调用工具，处理认证、资源、结果及故障；在普通会话内可用 | A05、A06 |
| G06 | 操作交互网页 | 连接受控浏览器会话，观察页面、表单/按钮/标签页/上传下载，等待状态并验证结果；登录由用户接手 | A07、A10 |
| G07 | 操作 Windows 应用 | 找到目标窗口，读取 UI Automation 或截图，点击/键入/快捷键/滚动，再观察结果；用户随时接管 | A08–A10 |
| G08 | 使用项目说明与技能 | 加载适用的 AGENTS.md/技能，按需取参考材料；可查看启用内容，不被无关文件指令扩大权限 | A11 |

| G11 | 安装、停止、恢复并持续使用 | 同事能独立配置、识别依赖、检查进度、停止、恢复和反馈；当前安装包通过全部支持范围测试 | D01–D05、D12–D18、A13 |

读文件、调工具、屏幕点击各自成功仍不等于任务完成；G04/G10 是强制组合验收。

## 3. 支持矩阵与边界

- Windows 11 x64 标准用户；至少两套干净环境。普通文件/文档/桌面能力不要求用户安装 Node/npm/MSVC。开发项目所需 Git、语言运行时、包管理器等按项目声明检测并说明；缺少依赖不能假装已运行，也不默默安装任意软件。
- 先认证一套支持工具调用、流式和图像输入的模型组合。可以是一个模型，或明确说明的文本模型与视觉模型组合；保存像素传递证据。图像不支持时明确禁用相关视觉路径，不能仍宣称完整通用版已验收。
- CLI 首发 PowerShell/cmd 和已验证的常用命令；至少一个 TypeScript/JavaScript 仓库和一个 Python 仓库完成真实修改与测试。不承诺所有语言、交互 TUI 或任意原生命令都支持。
- MCP 同时支持本地 stdio 和远端 Streamable HTTP，包含常见 token/OAuth 认证路径。用户可添加自定义兼容服务器；“兼容 MCP”不是“所有服务器已验证”。首批实测服务器、协议/SDK版本、认证方式逐项记录。
- 浏览器先维护一个 CDP 后端；复用现有接口。支持浏览器版本、下载目录、附加/专用会话策略写入发布说明。扩展后端不作为本版依赖。
- 桌面首批必须包含记事本、资源管理器，以及试用者实际使用的一款 Office/WPS 应用与明确操作；额外验证一个无法仅靠 UI Automation 完成的视觉目标。固定版本、125%/150% DPI 和多显示器环境需有证据。
- GUI 自动化不承诺绕过 UAC、安全桌面、验证码、登录或管理员权限；遇到这些状态暂停交给用户。Windows 窗口控制不能被宣传为文件沙箱内执行。
- 技能至少支持现有内置技能与 SKILL.md 目录的有限兼容子集；子任务默认最多两个同时运行，首发不递归派生，主任务持有写入权。无需插件市场、无限自治 Agent 或分布式执行。

支持矩阵在 A01 确认可行性，A13 依据安装候选实测冻结。缩小个别应用/语言支持可以明示，但不能删掉整个必需能力类别后仍称完整交付。

## 4. 统一的运行与交互契约

继续复用一个 Agent/Session/LLM/Memory/执行链和现有 SQLite。CLI、MCP、网页及桌面是工具适配器；不新建第二个聊天循环或任务调度内核。接口原则见 [能力实现手册](../agents/general-agent-capabilities.md)。

默认助手能发现本任务可用的能力；动态加载只减少上下文，不取代宿主授权。不可用工具告诉用户缺什么。任务内已获授权的普通读写/执行连续完成，不逐步重复询问；删除、对外提交/发送、提升权限和扩大范围按实际影响决定。用户要求修改项目已授权范围内代码，无须每改一行再确认。

进程、浏览器会话、窗口观察、MCP 请求与子任务关联同一 run。取消后拒绝新副作用，明确已发生的操作；不把关闭网络连接等同撤销远端操作。遇到未知写入不自动重放。

Computer Use 采用“观察→动作→等待→再观察→验证”的循环。截图须真正传给支持图像的模型；工具返回路径或 click 成功不足以证明看到页面或完成目标。原生桌面涉及用户当前桌面，控制状态、目标窗口、暂停/接管与停止必须清楚可见。

## 5. 交付门槛

### A02实施选择：沿用文件工具

项目上下文增强现有read_repo，不新建IDE或索引服务。固定只读Git命令识别工作树根/当前目录、已改/已删与未跟踪内容；未跟踪内容遵循Git忽略规则，选定范围内的实际文件仍须通过现有Path gateway，删除项只列状态不强读。摘要读取有限项目脚本，内容当资料。默认助手按需发现该能力。读后写版本、差异和撤回继续在原文件工具及成果呈现链内实现，保留用户已有修改。

- D 系列的 40 次基础任务是中间里程碑，不再定义完整 1.0。
- 完整通用版使用 [扩展验收](../agents/general-agent-acceptance.md)：50 个任务各两次，共 100 次。Beta ≥85/100 且每组≥8/10；稳定候选≥95/100 且每组≥9/10，无未解决 P0/P1。
- 同一候选的真实模型、安装、原生 GUI、MCP 传输和组合任务必须有证据；模拟协议测试不能替代。
- 至少 3 位同事使用 5 个工作日，合计≥30项任务，≥90%无需作者救场；覆盖新能力，至少一位有实际代码/CLI任务。详细覆盖与重试计分见扩展验收。
- 这是一组限定样本的交付目标，不是任意任务成功率承诺。

## 6. 不做什么与投入纪律

Prism、钉钉继续排除。远程 Worker/Relay、企业多租户、全量 Lux 复刻、双浏览器维护、媒体生态、公共云账号、无人值守跨应用自治不进入本版。MCP、单浏览器、原生桌面和有界子任务已经进入正式范围，不能再被旧冻结条目排除。

沿用 [安全投入上限](../agents/safety-budget.md)：新安全/治理框架约10%，最多15%；优先任务质量。命令取消、文件冲突处理、GUI目标识别、MCP凭据保护是对应功能的必要行为，以有限具体用例实现，不能扩成新企业安全平台。

总路线、当前工期估算与重估点统一见 [D+A 任务图](../work/general-agent/plan.md)。该估算替代旧版完整交付6–10周说法，不是期限承诺。
