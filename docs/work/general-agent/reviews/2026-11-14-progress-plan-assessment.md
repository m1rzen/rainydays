## 六项补充计划的可行性与必要修订

1. **任务收敛可沿 A14/D04 实现。** 现有 `task_create/task_update`、运行中 steer 和任务提示已存在。补充目标产物与完成条件时，需要能被宿主记录的阶段、完成依据和有界复核次数。用户明确要求交付后，下一轮先生成或返回当前产物，只保留解决成品阻塞的检查。仅修改提示词无法稳定约束换命令、换脚本形式的重复检查。简单问答继续走直接回答路径。
2. **本地图像观察是已有 A08 的缺失入口。** `filesystem-lux.ts` 的图片分支只返回 MIME/字节数并建议调用 image_helper；`agent.ts` 的观察工具集合仅有 browser_screenshot。应先接本地 PNG/JPEG 与文稿渲染页，明确主模型直读和独立视觉配置的路由。现有每轮只发最近两张图，逐页检查需分批并保存页码、文件版本/摘要、观察与检查结果；相同版本复用，版面变化后重验。小字允许对关键区域裁切或分辨率升级，不能只复用浏览器 1280 长边的策略。
3. **成品登记应早于跨会话问进度。** `document-outputs.ts` 当前只从 create_docx/create_xlsx 成功回执产生列表，脚本、通用 write 和下载保存均不在统一登记链。增加显式登记并核对授权路径、存在性、实际格式及版本摘要，区分原始资料、中间件和交付件；任务与会话归属必须持久化。多候选时显示选择，不能按最新 mtime 或最近 PDF 自动猜测。跨会话查询继续满足用户当前可访问范围。
4. **length 恢复须与断线重试分别设计。** `completedMessage()` 当前把 length 作为确定性不完整结束，测试也明确要求不重试。应保留完整工具参数的执行前提，将长文或生成脚本分成已验证的章节/片段，以检查点保存输入版本、运行环境、完成章节、产物和下一步；新请求从有效检查点重新生成缺失部分。残缺 JSON 或半段代码不可直接补接后执行。章节写入和最终发布需要防重复，断线、重启、取消后的续接都要回放。
5. **模板和语义检查适合通过 A11/D07/D08 补齐。** 模板可稳定结构和截图阅读宽度，事实判断还需独立标注样本。金额上下限、统计主体、包含关系、风险维度、意向/承诺/落实程度及无依据执法结论分别设正反例。事实保真、语言表达与版式分项评分。最低两页适用于本次后续明确约定的会议文稿，不能变成所有纪要的通用扩写规则。
6. **24 次回放适合本轮回归。** 开工前固定八项场景、材料/模型/解码配置、允许交互、时间预算和判定规则。由同一冻结候选完成，失败与重测分列。多个变体来自同一批海关材料，仍需保留原 A13 的跨领域覆盖。约 53 分钟是一次端到端观测，可作为参考，耗时减半需同时记录模型等待、工具耗时及主动人工时间，质量条件先满足再比较速度。

重复用户消息在 75 毫秒内出现三次是需要调查的现象。先关联客户端发送标识、服务请求、持久化消息和分支复制来源；确认传输重复后，再增加同一逻辑请求的幂等处理。不能按相同文本直接删除合法重复提问。
