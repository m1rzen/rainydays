### P05 根因与修复（2026-11-12）

复查 P05 完整工具记录后更正上面的判断：超时不是读写相对路径基准不同造成的。`read_repo` 把仓库根目录逐字节百分号编码，连 `-`、`.`、`:` 都编码（如 `95f9%2Defcec…`）；模型把 `%2De` 读成 `-de`，拼出多一个字母的绝对路径，`execute_command` 的 cwd 和 `edit_files` 因此被授权拒绝，随后反复试探路径直到超时。另发现评测脚本按工具名配对并行调用的结果，会把记录里的输出错位（只影响评测记录，模型收到的结果按调用 ID 对应，无误）。

修复：`read_repo` 的路径保留字母（含中文）、数字和常见路径符号 `/ . _ - : \ ( ) + , = @ ~` 原样，只编码空格、控制字符、bidi 控制符以及 `#`、反引号、`*`、`<`、`>`、`|`、引号、`%` 等可伪造结构的字符；评测脚本改按 toolCallId 配对。真实模型重测 P05 三次 3/3 通过（64、75、84 秒），无一次授权拒绝。
