## 4. 投入与决策点

按一名熟悉项目的维护者持续配合Codex估算：A01后基础与新增工程合计58–96工作日，另计5个试用工作日，约13–21周；模型、账号、机器等待另算。[实际探针](prototype.md)发现CLI运行时/模块解析与MCP原始管道适配缺口，相比原估算增加3–6日；A03真实Node/Python项目跑通后重估。包含已有D任务与重复验证的合并成本，不能再把旧26–45日直接相加。全部Lux定向研究含在其中，约5–8人日上限。本节为唯一当前工期估算。

A01已完成五项工程问题的调查，失败场景已交接A03/A05/A07/A08/A09。若视觉质量或隔离CLI兼容性不达标，先替换/调整该适配器或认证模型；大改内核需比较证据。

每一阶段至少一个普通会话可演示成果。连续两周没有新增结果，停止扩张并定位阻塞；不以新增安全/治理框架弥补模型或驱动质量。新增安全/治理投入上限仍为10–15%。

## 5. 执行与验收

按[workflow](../../agents/workflow.md)处理票据。每票先读现有代码与研究资料，实施一个完整路径并留下可重复结果。任务过大时在该票内拆出明确子步骤与证据，必须保持正常产品入口能验证，不能整层“底座”开发数周。

路线已整体批准；按依赖连续执行，无需逐票重复确认。票据状态以各文件为准，依赖未满足时不能因ready而跳过。真实付费评估、外部账号和实际对外发送仍按相应授权核对。验收标准唯一入口为[通用验收](../../agents/general-agent-acceptance.md)，基础结果可以复用，不可替代新增能力。
