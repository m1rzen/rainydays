## 用户结果与工作范围

将浏览器/桌面/MCP工具图片接入LLM图片消息。保留tool call与观察关联、目标、时刻、图像尺寸和缩放；控制图片数量/分辨率/上下文预算，保证坐标转换。记录模型视觉能力并提供缺失时的明确状态。先用合成非敏感图测试，再认证真实模型。

## 先读与研究

A01确认用户图片可投影PNG data URI，但tool附件被当前投影明确拒绝。见[原型](../prototype.md)，补宿主工具观察适配到提供方实际支持的图像消息格式，保留tool call/目标/时刻/坐标关联；不直接发送SDK不支持的tool图片结构，也不把宿主观察当成新的用户权限。

src/llm.ts、tools/image-helper.ts与工具结果投影；D02模型契约、D03预算。不能只把PNG路径拼进文本提示。

## 2026-11-12 实现与验证

起点 bfcb991。先实测模型池视觉能力：Gcable-Pro-Thinking、Pro、Plus、Max、Plus-Thinking 都能读图（生成图中红色方块中心 290,70，Pro-Thinking 回答 290,70；Thinking 模型需要足够的 max_tokens，否则内容为空）。

- **观察登记**（`src/observations.ts`）：宿主工具产生的图片登记到本会话观察库（用户数据目录，每会话最多 40 张，超出删除最旧），记录 sha256、发送尺寸、原表面尺寸、缩放、来源、目标、时刻、是否视口截图。只有登记过的图片可被投影；工具结果里伪造的摘要或其他会话的摘要不会附上任何图片。
- **截图缩放**：`browser_screenshot` 长边不超过 1280 像素，按 CSS 尺寸和 PNG 实际宽度记录缩放；视口截图用滚动偏移作裁剪原点（实验确认裁剪使用文档坐标）。
- **请求投影**：OpenAI-compatible 的 tool 消息不能带图，因此工具块之后插入一条 user 消息，写明调用 ID、目标、时刻、图片与页面尺寸及换算方法，并附 data URI 图片；每次请求只附最近 2 张，更早的改为文字引用。配置未启用图片输入（providerType 非 `openai-compatible-vision`）时明确告诉模型截图没有交给它。观察只存在于内存消息中，不写数据库、不进日志。
- **预算**：`estimateProjectedRequestTokens` 不再把图片 base64 当文字计数，每张按 1600 token 估算。
- **新工具** `browser_click_point`：按最近一次视口截图的图片坐标真实点击，系统换算回页面坐标；整页截图、导航后的旧截图不能用于定位点击。

验证：`tests/product/a08-observations.test.mjs` 4/4（图片数据而非路径、调用关联与说明、不支持图片时的提示、伪造/跨会话摘要不附图、只附最近 2 张、图片预算）；真实 Chrome 中按图片坐标点中画布目标、点空白判未中、越界拒绝、整页截图缩放至长边 1280 且不可定位点击（A07 集成测试文件，9/9）。产品 177/177、UI 15/15、桌面 6/6。

真实模型（Gcable-Pro-Thinking，视觉配置）`visualCanvas`：画布随机位置红色圆＋蓝色方块、绿色三角干扰，页面文字不含位置，命中编号只在点中后由服务端返回。3/3 通过（26、20、21 秒），每次首击即中并报告编号，未用 eval/直接请求。对照 `visualWithoutImages`（不启用图片输入）2/2 未编造：模型没有声称看见，分别改用 image_helper 视觉工具和自写脚本分析截图像素后点中，并如实说明方法。

未完成：真实运行中视口小于 1280，缩放为 1，缩放后的坐标换算只由工程测试覆盖；MCP 工具返回的图片（M04）尚未登记为观察；桌面截图在 A09。状态 implemented。
