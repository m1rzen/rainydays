## 用户结果与工作范围

让同一默认助手完成项目理解→失败重现→编辑→运行检查→解读结果→有限修正→交付差异。支持JS/TS与Python两个小型项目。检查命令从项目约定选择，区分环境问题、既有失败与本次回归。默认最多3次自动修正，无进展停止并说明可继续路径。

## 先读与研究

src/agent.ts、llm.ts与实际运行链入口（实施前定位）、A02/A03结果接口、项目指令加载已有路径、任务上下文预算。

共同实现原则见[能力手册](../../../agents/general-agent-capabilities.md)。实施前查当前定义与官方资料，记录实际版本；不要凭旧文档猜接口。

## 验收条件

- [ ] C01/C02/C05真实模型与真实工具完成；不能把模型自称通过计作测试证据。
- [ ] 最终显示本次diff、实际检查命令/退出结果、未验证项和仍失败原因。
- [ ] 保留dirty工作树；失败后不重置用户修改、不无授权提交或安装依赖。
- [ ] 同一失败无进展时有限退出，取消中止后续修正和进程。
- [ ] 工程桩与真实模型结果分别记录；配置/预算未获授权时保持真实验收待办。

## 验证接口与证据

普通助手对两个脱敏仓库的完整任务；可控模型桩覆盖失败分类/停止，实际模型完成能力验证。

计分与真实模型授权见[通用验收](../../../agents/general-agent-acceptance.md)。工程桩与真实结果分别记录；没有实际执行的条件不能勾选。

## 范围与回退

不重写Agent循环，不造专门通过测试的第二套运行路径。不以全新IDE、完整Git客户端或跨机器构建为依赖。

保留他人修改和用户数据；变更按本票独立提交，回退仅针对自身变更。涉及数据迁移先准备测试副本与恢复路径。复用[安全预算](../../../agents/safety-budget.md)，只加本能力需要的边界检查。
