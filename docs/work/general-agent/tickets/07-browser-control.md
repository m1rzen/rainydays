## 2026-11-12 实现与验证

起点 16c90d1。保留一个 CDP 后端，只替换原型已证实不足的动作：
- **真实输入**：点击改为元素可见中心的 `Input.dispatchMouseEvent`，被其他元素遮挡或不可见时拒绝；`fill`/`type` 改为聚焦后 `Input.insertText`，并核对页面实际保留的值；`press` 改为 `Input.dispatchKeyEvent`，支持 Enter、Tab、Escape、方向键、Space 及 Control+A、Shift+Tab 等组合。
- **引用新鲜度**：填写/输入后引用仍有效；主框架导航（`Page.frameNavigated`）、节点被替换（仅作废该引用）、交给用户后全部作废并要求重新快照；引用绑定所属标签，不能在其他标签使用。快照显示输入框当前值、勾选状态、已选文件和焦点（密码只显示掩码）。
- **标签归属**：连接用户已在运行的浏览器（cdpPort/cdpUrl 或已开的 9222/9223）时，只看得到本任务新开的标签及其弹窗，`browser_open` 新开标签而不导航用户标签，关闭时只关这些标签。
- **新工具**：`browser_wait`（等文字出现/消失或网址变化，响应取消）、`browser_upload`（经授权通道读取一个文件，只把副本交给页面）、`browser_downloads` 与 `browser_save_download`（RainyDays 自启浏览器的下载先进私有临时目录，不算成果，保存时经授权写入成果目录；连接用户浏览器时不改其下载设置）、`browser_handoff`（登录/验证码交给用户，无界面浏览器拒绝，之后旧引用作废）。
- **Agent**：成功的页面操作后，再次观察（快照、截图、等待等）不计为重复调用；同一动作重复三次以上仍拦截。操作结果的提示改为如实说明引用状态。
- **读取回退**：相对路径 `read` 在资料目录找不到、成果目录有同名文件时读取成果目录并注明来源（实测中模型保存下载后读回核对失败，曾转而全盘搜索）。

验证：`tests/integration/a07-browser-real-input.test.mjs` 7/7（真实 Chrome：B01 真实 Tab 移焦点、Enter 提交原生表单、等待页面更新；B02 节点替换与导航后旧引用报错、遮挡元素不点击；B03 上传单文件副本、下载完成后读回字节一致；连接用户浏览器只见任务标签、弹窗归属、交接后引用作废、关闭保留用户标签；无界面浏览器拒绝交接；重复调用规则）。ECO-08 原有浏览器测试 6/6（填写后引用不再作废的断言随行为更新）。`read-output-fallback` 1/1。产品 173/173、UI 15/15、桌面 6/6。

真实模型（Gcable-Pro-Thinking）`browserForm` 探测：本地报名页填写姓名与邮箱、Enter 提交、读出只有服务端知道的确认编号、点击下载报表并保存到成果目录，3/3 通过（101、127、139 秒），未使用 browser_eval/browser_fetch/curl 代替页面操作。此前失败的 6 次均为测试问题：评测框架拒绝了所有工具确认；测试页两个输入框却无提交按钮，按 HTML 规范回车不会提交（模型自行查明并如实报告，未绕过）。过程中暴露并修复了快照不显示字段值和观察被误判为重复调用两项缺陷。
