## 反馈循环与假设

命令：`node --test --test-concurrency=1 tests/electron/startup-recovery.test.mjs`。前两个场景经真实Electron/本地HTTP/renderer操作复现，直接检查状态和实际内容。

1. 缺失部门目录阻断所有操作：反证为缺失部门目录时`/api/files/roots`返回200、该根available=false、本地文件可用。用户补充Z盘需要公司内网，Claude因此改为缺失目录；这解释配置意图，不能据此把所有400归因Z盘。

4. 后台退出或工作台超时：独立观察服务日志与正常退出/重启；不能用前两项修复宣称历史偶发退出根因已知。

## 已确认原因与修复

- 文件根路由把SessionPersonaChangedError统一转换为400，丢失错误代码。现在返回409与SESSION_PERSONA_CHANGED，保持拒绝发放旧运行权限。
- 文件标签显示“打开原对话”，复用已有只读历史与“使用新版助手继续”路径；不更改绑定、删除旧消息或自动创建新权限。
- 可用根选择现在同时清空失效根的相对子路径，缓存命中也重新核对选择；缺失目录禁用，本地输出仍可访问，设置可换回有效工作目录。

初次红：旧定义场景实际400≠409；移走目录场景等待可用列表超时。修复后二者通过，原消息及附件内容在UI/内容API可核对。
