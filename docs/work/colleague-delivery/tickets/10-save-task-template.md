# D10 把成功任务保存为可编辑模板

Kind: implementation

Status: proposed

Spec: [同事版交付规格](../../../specs/colleague-delivery.md)

Research: [技术资料：同事版研发](../../../research/technology-stack.md#同事版研发2026-10-18)

Blockers: [D04](./04-run-stop-and-recovery.md)、[D08](./08-document-quality.md)

User stories: U09

## 用户结果与工作范围

1. 在成功任务/成果附近提供单一“保存任务”入口，填写名称、目标、可替换输入、输出规则与指令。
2. 保存版本化的最小元数据，创建前让用户检查；不生成需要 npm 安装的脚本工程。
3. 模板触发普通 run；source session 只作参考，旧授权与密钥不进入模板。

## 先读与研究

src/routine.ts、playbook.ts、managed-path-store.ts、session.ts、Agent；先选能复用的 metadata 存储。

与 Lux 有直接对应且尚未解决的问题，按 [有界研究计划](../../../research/lux-reference-plan.md) 只研究本票需要的行为。已有材料足够就直接记录复用决定。外部库/API 有变化时读已安装定义与官方资料，不凭记忆更换技术栈。

## 验收条件

- [ ] 保存、重命名、编辑、删除/归档、重启读取模板可用；已有会话不被修改。
- [ ] 导出的可分享元数据不包含凭据、旧任务许可、原附件正文或不可编辑的个人绝对路径。
- [ ] 从成功报告保存模板后可换输入得到新报告；结果走现有成果区。
- [ ] 真实研究未验收时可继续模板工程，但不能让此项使整版质量 gate 通过。

## 验证接口与证据

模板持久化公共接口 + Electron 保存后重启重跑；复用普通 Agent 合成模型，不新建另一个 runner。
通用计分与证据口径见 [acceptance](../../../agents/acceptance.md)。本票通过需要所有验收条件有实际证据；未测部分明示，不能以旧报告代替。

## 范围与回退

不同时推出 Playbook 与 Routine 两套普通用户入口，不增加脚本编辑器。
保留其他人的改动。数据结构变化先保存可恢复测试快照并明确兼容；代码按本票独立提交，回退只针对该提交，不能重置他人工作。
