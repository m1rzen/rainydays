# D14 普通用户可恢复的备份与升级

Kind: implementation

Status: proposed

Spec: [同事版交付规格](../../../specs/colleague-delivery.md)

Research: [技术资料：同事版研发](../../../research/technology-stack.md#同事版研发2026-10-18)

Blockers: [D13](./13-installer.md)

User stories: U11

## 用户结果与工作范围

1. 将现有可靠备份/恢复链连接到可理解的用户入口；说明包含什么和不包含什么。
2. 升级前一致快照、失败保留原数据；处理旧 schema 和新版本数据不能倒灌的问题。
3. 恢复前展示来源/时间/影响并保存当前快照，恢复后核对会话/附件与成果引用。

## 先读与研究

data-backup.ts、managed-restore.ts、bootstrap-database.ts、session.ts、历史恢复脚本与已有 rt09/data01b 用例。

与 Lux 有直接对应且尚未解决的问题，按 [有界研究计划](../../../research/lux-reference-plan.md) 只研究本票需要的行为。已有材料足够就直接记录复用决定。外部库/API 有变化时读已安装定义与官方资料，不凭记忆更换技术栈。

## 验收条件

- [ ] 备份后新建任务，再恢复测试副本，能证明新数据被保护或可另行导入。
- [ ] 升级中断、恢复中断、WAL reset 场景不损坏原数据；历史附件字节可核对。
- [ ] 卸载保留数据与清除数据两种选择行为一致；用户成果目录不被当缓存清理。
- [ ] 用户可以按指南完成恢复，不需要手工覆盖 SQLite 或运行开发脚本。

## 验证接口与证据

复用 WAL、history-recovery、rt09、managed-restore 与当前包升级恢复路径；只操作测试数据。
通用计分与证据口径见 [acceptance](../../../agents/acceptance.md)。本票通过需要所有验收条件有实际证据；未测部分明示，不能以旧报告代替。

## 范围与回退

不建设云备份、多设备同步或通用灾备平台；不扩大保存真实数据的报告范围。
保留其他人的改动。数据结构变化先保存可恢复测试快照并明确兼容；代码按本票独立提交，回退只针对该提交，不能重置他人工作。
