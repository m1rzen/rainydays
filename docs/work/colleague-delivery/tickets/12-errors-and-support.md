## 用户结果与工作范围

1. 统一用户能区分的错误类别和下一步，保留实际 run/版本/错误编号。
2. 显示当前阶段与已生成成果；按实际 observation 提供请求数、耗时、usage，费用缺数据时显示未知。
3. 复用现有诊断包，导出前预览范围；不默认收集正文。

logger.ts、observability.ts、model-connection.ts、electron 恢复页与现有诊断导出。

与 Lux 有直接对应且尚未解决的问题，按 [有界研究计划](../../../research/lux-reference-plan.md) 只研究本票需要的行为。已有材料足够就直接记录复用决定。外部库/API 有变化时读已安装定义与官方资料，不凭记忆更换技术栈。

## 验收条件

- [ ] 额度、认证、断网、目录失效、解析失败、权限拒绝、应用故障都能从界面采取下一步。
- [ ] 长任务和失败时不留下无解释的无限等待。
- [ ] 诊断中无密钥、完整提示/附件正文；用户主动导出，应用不自动外发。
- [ ] 一次事件只统计一次；费用估算与实际值标识明确。

## 验证接口与证据

现有 observability/redaction/连接错误测试，UI 检查两个代表错误和一次诊断导出。
通用计分与证据口径见 [acceptance](../../../agents/acceptance.md)。本票通过需要所有验收条件有实际证据；未测部分明示，不能以旧报告代替。

## 范围与回退

不建设遥测平台、全 SQL 插桩、性能指标数据仓库或自动故障归因 Agent。
保留其他人的改动。数据结构变化先保存可恢复测试快照并明确兼容；代码按本票独立提交，回退只针对该提交，不能重置他人工作。
