# 同事版研发任务图

日期：2026-10-18；Status: proposed。用户要求完整可执行规划，故一次提供全部候选卡供审阅；尚未将新增实现视为获批或完成。每张任务独立文件，整体批准后按依赖执行即可，不需逐卡重复索取相同授权。

产品范围由 [规格](../../specs/colleague-delivery.md) 定义；真实执行状态回填各票，当前下一步由 [STATUS](../../STATUS.md) 指定。D 系列补齐 R4–R7 的交付细节，沿用 R1–R5 已验证成果，不要求重新做一遍。

## 六个阶段

| 阶段 | 主要任务 | 可演示出口 | 预估维护者投入 |
|---|---|---|---|
| M1 稳定地开始和停止 | D01、D02、D04、D05；尽早 D13 | 无部门盘的同事机器能启动、配置、停止 | 约 5–8 日 |
| M2 可靠理解资料并产出 | D03、D06、D07、D08 | 真实来源、可检查长文、可编辑成果 | 约 6–10 日 |
| M3 整理与重复工作 | D09、D10、D11 | 预览整理、保存成功任务、换输入再跑 | 约 5–8 日 |
| M4 可安装、可恢复、可支持 | D12、D13、D14 | 当前安装候选、恢复入口、错误处理 | 约 4–7 日；D13 提前试验计入此阶段 |
| M5 证明同事可用 | D15、D16 | Beta 40 次任务、三人一周试用 | 约 3–5 日工程 + 5 个试用工作日 |
| M6 稳定并交付 | D17、D18 | 稳定候选、文档、维护接手 | 约 3–7 日，随真实缺陷重估 |

合计粗估 26–45 个工作日，另需一周试用窗口；这是任务量推算，不是工期承诺。假设一位持续投入的熟悉项目维护者 + Codex，模型、用户和测试机器可用。D01/D02 后用实际完成速度重估。Lux 研究包含在阶段内，首轮不超过 3–5 人日。外部等待另计。

默认可执行顺序：D01 → D02 → D04 → D05 → D13（早测安装）→ D03 → D06 → D07 → D08 → D09 → D10 → D11 → D12 → D14 → D15 → D16/D17 → D18。按真实阻塞调整，依赖表优先于这个建议排列。

- D03/D04 对 D02 的依赖仅为本地协议契约和确定性回归已验证，具体见票据 Blockers；证据记在 D02，D02 整票在真实模型认证完成前仍未 verified。D07 的真实验收则需要可用的已批准配置。其余依赖默认要求整票 verified。
- D07 被额度阻塞不妨碍 D08–D14 中不依赖真实研究的工程；D15 是整版质量出口，必须补齐 D07。不得借并行实施把 R4 验收跳过。
- D13 不必等全部功能齐全才发现 ABI/打包问题；最终候选仍要重验受后续变更影响的安装行为。
- D17 依赖 D15，允许在 D16 试用过程中收到缺陷就修；D18 同时要求 D16/D17 完成。
- 同时最多一个主要功能切片和一个必要阻塞修复。依赖可并行表示可以选择下一条工作，不要求多 Agent 同时改共享目录。

## 扩展候选

以下只给触发条件和最小探索边界，**不进入 1.0 依赖，也不创建 ready 票**。

| 候选 | 何时值得做 | 最小版本与证明 |
|---|---|---|
| 一个交互浏览器后端 | ≥3 个反复出现的网页任务无法用公开提取完成 | 一个后端，用户处理登录，3 个固定任务可恢复；避免 CDP/Extension 双养 |
| OCR 或 PPTX | 试用持续因这些输入/输出受阻且收益明确 | 先选一种格式，固定资料测正确率与费用；不同时扩全格式 |
| 可编辑偏好/项目记忆 | 同事每次重复相同偏好且普通模板不够 | 明确保存/查看/改正/删除，无跨项目暗中串用；不做自治记忆图谱 |
| 受限代码分析增强 | 常见表格计算/转换用现有工具无法完成 | 复用隔离，单个可核对计算任务，取消与资源上限 |
| 本机定时重复 | 手动模板稳定且 ≥3 个规律任务有需求 | 明确应用须运行、有限范围、新输入失败可见、去重；不开发远端调度 |
| 单个系统连接 | 某系统成为重复手工步骤的主要成本 | 只做那个连接；Prism、钉钉继续排除 |
| 多 Agent | 单 Agent 实测瓶颈确是可并行工作 | 有界 A/B 比较质量/费用/耗时，收益不足就保持单 Agent |

## 周度检查

只回答三件事：本周哪个用户流程变好了；实际失败最多在哪里；下一周最小闭环是什么。若连续两周没有新增可用结果，停止新功能，对瓶颈做一个有明确退出条件的实验。重写内核需实际比较证据，不能由焦虑或代码规模触发。
