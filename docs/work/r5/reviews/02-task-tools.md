# R5-02 代码审查

2026-09-30。固定起点 68ecfc7；范围为此提交之后的 R5-02 工作树与新增 TaskToolSelection、产品行为用例。分别执行 Standards 和 Spec 两次审查，无委派。无未解决阻塞发现，以下修复交由最终行为验证。

## Standards

- **P1，兼容性，已修复**：默认 Persona 的来源摘要变化会使旧会话运行环境拒绝创建。原选择接口没有返回可识别状态，界面静默留在其他会话。src/index.ts 的选择接口现返回 SESSION_PERSONA_CHANGED 与原会话信息；选择只读历史不签发能力，原摘要保留。public/renderer.js 显示原回答和明确的继续入口。真实重启用例在修复前只显示定义变化错误，无法看到原回答。
- **P1，数据完整性，已修复**：原 rollback 在运行环境不存在时也删除回答；“重新生成”可能先删除旧回答再发现定义不兼容。现在先确认运行环境可用才删除消息，定义变化返回 409。原构建实测回退返回 200，新增断言变红；修复后须检查原回答与附件仍可复制。
- **P2，选择一致性，已修复**：只读历史选择必须与服务端 UI selection 一致，否则列表刷新会换回另一会话。状态更新留在既有运行环境变更队列，既不创建旧能力也不修改原绑定；原生日常切换和刷新用例覆盖。
- 默认工具集合只是本轮可见协议。所有实际调用仍经过 authentic Broker、schema 检查、路径/网络/执行网关。成功的 search_tools 宿主回执只能加入当前允许协议；网页、正文、失败、截断不能激活工具。发现和调用同批时，调用必须等下一轮。集合不落库，每次 Agent.run 重新创建。
- 非 general 助手、没有 search_tools 的兼容助手保留完整工具行为。现有高级 Persona 文件、执行隔离、授权链未改动。默认 Persona 清除固定机器目录，沿用 applyRuntimeSettings 的应用目录注入。
- 旧会话继续复用现有 fork，复制消息、附件、任务和固定指令，创建当前定义和新能力，不直接覆盖旧摘要或恢复旧任务许可。只读视图隐藏其他会话的任务/固定指令/后台列表，添加附件提示先创建副本。

## Spec

- 首轮实际提供十二项常用文件、网页研究和文档工具，其余允许的记忆、下载、任务拆分、受保护数据脚本等按发现加入。Media、Worker、浏览器控制、多 Agent、调度不再进入默认允许列表。
- 产品用例通过真实 Agent/Broker：未发现的 list_memories 被拒绝，发现后下一轮可调用；搜索父范围外工具不会得到能力；下一任务重新收敛。原生 Electron 覆盖真实模型请求 schema、发现后调用和新任务重置。
- 旧允许列表取自固定 790a097，改为仅用于测量的独立 fixture 身份，在同一版本 schema/运行链中对比：114 项 / 52,920 bytes → 12 项 / 8,119 bytes，工具描述 JSON 约减少 84.66%；发现后 13 项 / 8,433 bytes。该数字不是历史模型的完整请求、实际费用或耗时。
- R2 文档附件与生成/恢复/另存、R4 来源/报告已在默认工具收敛后通过原生 Electron 回归。旧定义专用重启用例验证只读历史、模型拒绝、回退拒绝、消息/附件字节复制和新副本继续，并检查原摘要未改写。
