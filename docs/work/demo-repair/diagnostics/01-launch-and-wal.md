# 启动与 WAL 误判诊断

2026-10-16。用户已授权修复审查中的三项问题。

启动假设：①缺少 npm_node_execpath 导致 ABI 不匹配；②构建过期；③模型配置导致启动失败。只读构建检查通过，普通 Node ABI 137 的内存 SQLite 可用，Electron ABI 148 加载同一模块明确失败，确认①。两个演示入口改用 npm exec，隔离用户目录从无 npm 环境实际启动通过（简易 15.25 秒，PowerShell 17.12 秒）。

数据假设：①SQLite 数据库真的损坏；②WAL 重置后旧代帧被误判；③部分写入造成当前事务校验失败。迁出库 quick_check 通过；WAL 1006 帧，第 211 帧开始盐值变化。SQLite 官方格式允许 WAL reset 保留旧尾部。用真实 checkpoint(RESTART) 后短更新生成同类日志，openBootstrapDatabase 稳定报 frame identity is invalid；修复前红、修复后绿。

修复仅在已经校验通过的提交边界后，识别两个盐值均变化的旧代尾部；保留当前代校验、头/长度/路径/版本校验。原有 11 种损坏和 2 种身份问题仍拒绝，证据文件不变。未忽略全部 WAL 错误或删除日志。

恢复采用现有会话导出/导入格式而非整库覆盖。CLI 测试先因工具缺失变红，随后验证追加两会话、一消息、三附件、保留新消息、默认仅预览、重复执行不重复。实际恢复前有副本演练和一致快照；恢复后原四会话、34 条消息、200 条审计记录逐行不变；新添两会话、一消息、三附件，附件名称/MIME/长度/摘要/内容/状态与迁出副本相同。
