## Standards

- 开发入口复用 npm 的 Node 路径，不重编译 SQLite，不改桌面 IPC 或鉴权。原生回归从无 npm 环境验证两个新入口的实际启动目标；PowerShell 入口仅在显式 --recover-normal 时跳过重复询问，正常启动仍保留原恢复提示。
- WAL 只接受已验证提交边界后的双盐旧代尾部。真实 SQLite reset 场景先红后绿；既有损坏日志矩阵仍拒绝，无源证据改写。长度/版本/身份约束保留。
- 新恢复脚本只追加缺失会话，复用既有消息/工具历史/附件验证和事务；不手工拼接业务表，不覆盖配置和当前审计链。导入当前助手定义，旧任务许可不继承。新会话 ID 与源 ID 私下映射，名称加“恢复”。
- 一致快照、完整副本演练先于写入；外层事务保证批次成功或回滚，索引意图在事务提交前写入，失败 ID 不存在时可重试。实际应用仍使用既有运行环境恢复锁；正在运行时需关闭后执行，不能并行覆盖。
- 无未解决阻塞发现。复核修复 no-unsafe-finally 清理写法；未扩大到模型探测、凭据迁移或部门目录配置。

## Spec

- 两个新入口都能从普通桌面环境启动源服务，简易入口转发参数，常规快捷入口指向已验证 PowerShell 目标。
- 缺失两会话、一消息、三附件已经追加恢复。实际恢复前后逐行核对当前会话、消息、审计表不变；原附件字节相同，后续检查无待恢复项。原迁出库和恢复前快照继续保留。
- 原 restore-db 不再移动整目录或复制旧库覆盖；需要明确来源数据库，默认仅预览，Apply 追加恢复。
