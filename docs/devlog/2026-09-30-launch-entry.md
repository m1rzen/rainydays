# 启动入口与真实桌面启动修复

## 用户遇到的问题

直接打开 `public/index.html` 后出现无样式页面和巨大的黑色图标。该文件使用应用服务的资源地址，并依赖 Electron 注入的本地 API 认证；双击 HTML 无法启动应用。

本次检查还发现真实开发入口存在两个缺陷：`electron electron/main.cjs` 使 Electron 使用错误的应用根目录；后台通过 Electron 的 Node 环境执行 tsx CLI，既与开发依赖的原生数据库 ABI 不匹配，又产生额外进程，使服务就绪消息中的 PID 无法与被启动的进程对应。

初版隐藏启动器直接调用 GUI 可执行文件后提前结束，造成 `EPIPE` 错误。该尝试已替换为由 npm CLI 持续等待桌面应用退出的方式。

## 修复

- 新增根目录 `启动 RainyDays.cmd` 与隐藏的 PowerShell 启动程序，完成构建后打开桌面应用，并在应用运行期间保持日志连接。日志统一写入忽略目录 `test-results/desktop-launch.log`。
- `electron` 和 `electron:dev` 改为通过项目根目录 `electron .` 启动。
- 开发后台采用 npm 提供的 Node 可执行文件，以 `--import` 加载 tsx 并直接执行源文件；Windows 加载器地址使用规范文件 URL。加载器、源码和可执行文件继续经过已有文件句柄校验。
- 直接打开 HTML 时，用可从本地加载的独立脚本和样式显示启动说明，移除无法工作的界面。
- 更新快速开始说明和本地资源断言，新增直接打开 HTML 与真实开发启动回归。

## 验证

- 构建通过；相关文件 ESLint 与差异空白检查通过。
- 启动提示、图标、文件界面、可访问性和 Electron 文件句柄检查共 15 项通过。
- 真实开发启动回归通过：使用源码入口和 npm Node，加载数据库，出现完整首页，应用内会话接口返回 200，样式和图标尺寸正确。测试未使用编译入口覆盖。
- 同一真实回归确认普通外部客户端访问会话接口仍返回 401。
- 用户本机应用已重新启动：后台在第 1 次启动进入 ready，重启次数为 0；RainyDays 正常窗口存在；首页及新版样式均返回 200。

Windows 受限执行环境的 GPU 子进程不能正常加载；真实桌面验证在获得本次启动授权的环境中完成。直接打开 HTML 的提示通过 DOM 回归验证，未宣称对该本地文件完成浏览器截图检查。
