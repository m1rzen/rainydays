# RainyDays 二次重构进度审计

## Scope and environment

本次按“少量熟悉用户使用的通用桌面助手”评估当前实现，检查四类目标工作：读资料并回答、研究问题、整理并产出文件、重复已验证任务。证据来自当前源码、产品路线、真实 Electron 流程、快速产品回归，以及工作树中尚未提交的 Playbook、Routine、浏览器、媒体、Worker 和下载能力。

本次不使用真实用户资料、现有 API 密钥或线上模型，也不把未提交代码和定向测试通过直接计为产品完成。

## Repository inventory

- Runtime and entry points: Electron 桌面应用、loopback API、Agent/LLM/Memory、Capability Broker、PathPolicy、隔离执行。
- Major modules and data stores: SQLite 会话与附件、PDF/DOCX/XLSX 分段读取、Word/Excel 输出、成果恢复、文件查看器、浏览器与重复任务 WIP。
- Build, test and deployment: 当前源码构建与 lint 通过；产品快速回归和真实 Electron 文档流程通过；当前安装包未重新验收。
- Existing documentation: `PRODUCT.md`、`DESIGN.md`、`docs/ROADMAP.md`、R1/R2 规格、任务、评审与诊断记录。
- Worktree and revision baseline: HEAD `b38b66f`；另有约 56 个已修改跟踪文件和多项未跟踪功能文件，主要是生态能力 WIP 与治理清单更新。

## Findings

### F1：核心文档任务已从原型进入可重复验证阶段

- Severity: informational
- Confidence: confirmed
- Affected behavior: 资料进入模型、断流、文档生成、成果预览与继续修改。
- Evidence: 产品测试 17/17、真实 Electron R2 流程通过、R1/R2 任务均为 verified。
- Likely cause: 二次开发先修正资料截断和断流，再围绕单一文档任务打通授权与成果。
- Recommended next action: 保持该闭环稳定，用真实模型和脱敏样本验证内容质量，而非继续扩大底层工具数量。
- Verification approach: 固定资料问答和文档任务集，核对事实、来源、文件可打开性和继续修改结果。

### F2：研究能力没有达到“结果可相信”的产品标准

- Severity: high
- Confidence: high-confidence
- Affected behavior: 多来源研究、事实与推断区分、引用和失败来源呈现。
- Evidence: 搜索、网页提取和浏览器能力存在，但没有 R4 规格、真实模型任务集或用户可见的来源成果闭环。
- Likely cause: 旧路线优先增加工具和生态契约，没有围绕一份研究报告定义端到端退出条件。
- Recommended next action: 只选一个搜索渠道和一个读取路径，完成 5 个可人工核对的研究任务；浏览器交互仅在网页提取不足时加入。
- Verification approach: 每个关键事实能回到实际读取来源；失败来源明确；报告引用与读取内容一致。

### F3：重复任务的底层能力领先于产品入口

- Severity: high
- Confidence: confirmed
- Affected behavior: 用户保存一次成功工作并用新输入重跑。
- Evidence: Playbook 和 Routine 定向测试分别 8/8 通过，但新版界面没有面向普通用户的保存、填写输入、运行和查看历史入口。
- Likely cause: 实现以工具契约和项目格式组织，缺少围绕用户成功任务的简单对象模型。
- Recommended next action: 在 Routine 与 Playbook 中只选一个作为首版内核，提供一个“保存为重复任务”的窄流程；另一个后移。
- Verification approach: 用户从成功会话保存模板，更换输入/输出位置后手动重跑；权限不扩大，失败可恢复。

### F4：默认能力和设置仍超过首版实际需要

- Severity: medium
- Confidence: confirmed
- Affected behavior: 首次配置、模型工具选择、错误理解和维护成本。
- Evidence: 设置有 11 个域，仅 Profiles/TTS/ASR 标记可用，其他域仍在界面显示；默认工具注册包含 Worker、Browser、Playbook、Routine、Media 等大量能力。
- Likely cause: 旧 parity 路线和当前产品路线并存，新增 WIP 继续进入共享注册表和 Persona。
- Recommended next action: 建立“普通模式”默认能力集，只含文件、研究、文档和必要执行；高级能力按需加载，设置隐藏待接入域。
- Verification approach: 测量真实请求的工具定义体积、工具误选、首次任务时间和用户是否需要解释内部名词。

### F5：治理负担仍然存在，并已再次干扰状态判断

- Severity: medium
- Confidence: confirmed
- Affected behavior: 开发反馈、功能完成判定和路线聚焦。
- Evidence: 下载行为用例大多通过，但 TOOL-06 因共享文件摘要变化导致治理测试失败；工作树仍包含大量 resolved 清单更新。
- Likely cause: 多张旧卡将共享源码哈希和任务证明复制进各自清单，普通功能修改造成大范围身份漂移。
- Recommended next action: 完成 R3 的最小迁移：快速产品测试只验证行为，发布候选再统一绑定产物身份；停止为未纳入首版的 WIP 继续扩展重复治理文件。
- Verification approach: 普通 UI 或工具修改不再要求更新多张无关卡；路径、凭据和执行边界变更仍运行对应负向测试。

### F6：当前最大的未知数是实际任务质量，而非运行时能力数量

- Severity: high
- Confidence: confirmed
- Affected behavior: 是否能给同事朋友稳定使用。
- Evidence: 当前验证均使用确定性模型或兼容 Provider 夹具，没有真实模型、脱敏资料、干净机器和目标用户数据。
- Likely cause: 先前开发主要用工程契约判定完成，真实任务评估尚未启动。
- Recommended next action: 冻结新生态能力，完成 20 个脱敏任务、当前安装候选和两至三名用户试用。
- Verification approach: 按路线图记录正确性、来源、文件可用性、耗时、请求数、审批次数和人工救场。

## Distance to the revised vision

- 工程基础成熟度：约 75%–85%。会话、文件、权限、隔离、恢复、文档解析和输出基础较完整。
- 已验证的用户任务覆盖：约 45%–55%。四类目标工作中，文档读写闭环较完整；研究和重复任务仍缺产品验收。
- 小范围可分发成熟度：约 35%–45%。真实模型质量、首次配置、安装候选和用户试用均未完成。

这些区间是阶段判断，不是通过文件数计算的完成率。若只看“可演示”，当前已经达到；若目标是让同事朋友不靠作者现场协助稳定完成工作，仍需要一个聚焦的 R3–R7 收口周期。

## Unverified areas

- 真实模型在中文长文、表格、多来源研究和文档写作中的正确率、耗时与费用。
- 当前工作树所有 WIP 合并后的全库、安装包、迁移与恢复行为。
- 扫描 PDF/OCR、图片资料理解、复杂 Office 版式和原文件无损编辑。
- 干净 Windows 机器上的安装、首次配置、凭据迁移、升级和卸载。
- 三名目标用户一周内的独立使用结果。
