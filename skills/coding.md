# Coding Skill

## 代码规范

- 使用清晰的变量命名，避免缩写
- 函数职责单一，超过 50 行考虑拆分
- 注释只写"为什么"，不写"是什么"
- 错误处理在系统边界做，内部代码信任输入

## Git 纪律

- commit message 用简洁描述，聚焦"为什么"
- 不提交 .env、credentials 等敏感文件
- 不 force-push，不 amend 已推送的 commit
- 每次提交前检查 git status

## 测试原则

- 改动后运行相关测试验证
- 单次运行模式（非 watch）
- 测试失败先读错误信息再修
- 不为不存在的场景写测试

## 文件卫生

- 优先编辑已有文件而非新建
- 不主动创建文档文件除非要求
- 创建文件前确认目录存在
- 不添加冗余的抽象和配置
